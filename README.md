# 开发管家（dev-butler）

开发管家是一个 Codex 插件，把猪齿鱼工作项、Codex 会话与本地 Obsidian 笔记关联起来。设计和验收步骤见 [架构](./ARCHITECTURE.md) 与 [验收用例](./ACCEPTANCE.md)。

## 从源码构建

需要 Node.js 20 或更高版本和支持插件的 Codex。构建前安装 npm 依赖。

```sh
npm ci
npm run build
npm test
```

这会从 `widget.js` 生成 MCP 页面需要的 `widget.bundle.js`。开发调试时，在构建完成后把该目录注册为本地插件市场并安装插件。直接从 Git 仓库取到的是源码，安装包需要另行包含运行依赖和构建产物。

```sh
codex plugin marketplace add .
codex plugin add choerodon-yuque-link@work-link-marketplace
```

确保 Codex 能找到 `node`、`c7n` 和 `codex`，并用自己的猪齿鱼账号登录。向本机 MCP 进程提供 `CODEX_LINK_VAULT` 以指定已经存在的 Obsidian 知识库路径。需要指定 CLI 路径时，使用 `CODEX_LINK_C7N` 和 `CODEX_LINK_CODEX`。如果桌面宿主未继承这些环境变量，可以在仓库外的本地插件副本中，通过所用 MCP 配置里的 `env` 设置，再注册该副本。旧版清单读取 `.mcp.json`，新版使用 `mcp.json`。

更新已有笔记还需安装 [Obsidian 桥](./obsidian-plugin/README.md)。Windows 上的桌面安装流程仍待实机验证。

## 当前范围

- 本地工作项与会话多对多关联、主工作项、草稿以及导入预览和冲突处理。
- Choerodon 通过本机 `c7n` 执行受限的只读查询；指定项目的工作项搜索可返回结构化数据，但不保证跨项目覆盖或分页元数据准确。
- 页面自动读取当前账号和项目首页，选择项目后默认精确过滤本人经办记录；可切换查看项目全部返回记录。它使用工作列表接口，可能含关联项，不保证与任务面板口径相同。不会自动排除已完成状态；分页通过显式页码查询。
- 工作项可通过 Codex 实验性 App Server 项目和会话列表，选择已有会话并经确认后保存本机关联；不读取会话正文。也可确认创建会话，使用工作项标题命名并发送预览的初始消息；创建或发送结果不确定时不会自动重复，需在创建记录中核查。项目接口依赖本机 Codex 版本和 `CODEX_LINK_CODEX` 配置，桌面列表显示可能延迟。
- 一个工作项可经确认关联多个 Codex 工程目录；关联纳入本地索引备份和导入冲突处理。添加时会重新核对项目列表，解除不会删除文件。按需检查只反映目录当时是否可访问，不扫描工程；失效记录会保留，也不证明远端工作项仍可访问。
- 创建结果不确定但已返回会话 ID 时，可在创建记录中核对 ID 与工程目录，再单独确认保存关联；核对不证明 Codex 桌面项目归属，且不会创建会话或发送消息。
- MCP 页面提供工作项查询、会话关联、本地草稿操作，以及知识库 Markdown 笔记的路径筛选和原文查看，不修改 Codex 应用本体。已有部分手动验证，知识流程仍待完整验收。
- 语雀只读适配器有模拟测试，真实语雀账号尚未接入；Codex 会话适配器已接入受限 App Server 操作，模拟测试不能替代当前桌面宿主的完整链路验收。

## Choerodon 重新登录

账号或项目加载失败时，可展开页面的“Choerodon 重新登录说明”。页面显示最近确认的账号、租户和 API 环境；刷新失败后，这些信息不表示当前认证仍有效。首次加载失败时，页面无法确定账号或环境，需先核对插件配置。失败也可能是网络、API 配置或项目权限问题，不能仅凭加载失败判断令牌过期。

在本机终端确认 `C7N_API_URL` 与插件使用的 API 环境一致，再运行 `c7n login`，在 CLI 的安全交互提示中输入该环境的个人访问令牌（PAT）。不要使用携带令牌的命令参数，以免进入终端历史；不要将令牌粘贴到页面。登录完成后点击“刷新账号和项目”，核对账号、租户及环境后重新查询。页面不会收集令牌或自动登录；刷新及重新登录不会删除本地草稿和关联。

## 知识库约定

关联会话的“总结会话生成草稿”使用本机配置的默认模型：先核对原会话最近已结束回合，再以该回合为边界创建临时会话副本，在只读、无网络且禁用执行工具的副本中总结。它继承原会话可用的持久上下文，不依赖最近一页文本，不向原会话追加消息，不创建侧栏中的持久会话。已压缩或尚未持久化的内容仍可能缺失；生成结束前若原会话出现新回合，则丢弃结果并提示重试。正文仅填入编辑器，保存及写入知识库仍由用户操作。

更新插件后需要重载插件的 MCP 服务，或退出并重新打开应用。仅关闭再打开管理页面会刷新界面，但已经运行的 Node 后端仍可能保留旧代码。

- 知识记录尽量使用标准 Markdown，不依赖 Obsidian 专属链接或插件格式，以便后续迁移。
- 图片和附件使用相对于笔记的路径，并与笔记一起备份；索引导出本身不包含完整知识库和附件。目录备份和恢复均有页面入口，真实知识库备份与恢复尚未验证。
- 工作项和会话关联保存在独立本地索引中，不依赖 Obsidian 内部标识。
- 知识库读写按可替换适配器设计；本地 Markdown 和未来语雀能力各自以实现及验证情况为准。后续迁移仍需处理附件和链接映射，不能保证无损或自动迁移。

知识草稿的目标位置支持浏览知识库目录或选择已有 Markdown 文档，无需手输完整路径。选择目录新建文档时，文件名默认根据标题生成，也可单独修改；目录浏览包含空目录并排除隐藏项和符号链接。选择位置只修改草稿目标，不写入文件。

知识草稿现在支持预览后新建 Markdown 笔记：确认绑定目标、版本和预览正文；已有文件不会覆盖。提交记录独立保存，成功后保留草稿；未知结果或重复版本阻止再次提交。目标父目录须已存在。实际知识库写入仍需用户逐次确认，自动测试仅使用临时知识库。

知识库配置、目标路径及父目录在创建提交记录前检查；检查失败不会写入笔记，修复后可重试。检查通过后的写入仍会再次验证路径，写入过程中出错时按结果不确定处理。

草稿写入前会本地检查部分常见私钥、Bearer 凭据和密码字段；发现疑似内容时阻止写入，需编辑后重试。检测可能漏报或误报，不能代替人工检查；已保存的草稿仍可能包含敏感信息，应谨慎管理和导出。

本地索引导出函数会检查所有字符串字段，发现上述疑似凭据时阻止导出，不删除或修改原数据；这不是完整的秘密扫描，导出前仍需人工审查。管理页面提供导入导出入口。

会话中可通过 `draft_list` 按状态分页查看草稿摘要，再用 `draft_read` 按 ID 读取单篇正文。更新草稿必须携带当前版本，避免覆盖其他入口的修改；保存草稿不写入知识库。

插件包含 `knowledge-capture` 技能，用于在用户要求沉淀知识或明确表示工作完成时，基于现有证据提出候选草稿；保存草稿和写入笔记分别需要明确确认。插件清单按本机已安装插件的技能路径结构注册；当前 Codex 桌面是否已加载该技能以及自动触发效果尚待实际验证，不应假设已有会话已加载新版本。

插件还包含 `history-reason` 技能，指导 Codex 先检查当前工程代码，再按需查询指定工作项关联的知识和会话，并区分事实与推测。它复用现有工具，不保证资料完整或可访问；读取关联会话历史仍需用户明确要求并确认。真实宿主是否发现该技能及自动触发尚未验证。

在工作项的已关联会话面板中，可请求基于原会话上下文生成知识草稿候选。生成使用本机 Codex 的实验性会话取样能力，不向原会话追加消息；候选仅填入可编辑草稿表单，不自动保存或写入知识库。原会话上下文可能经过压缩；其他进程中正在进行的回合可能未包含，不能保证覆盖完整历史。

生成会禁用 MCP 并检查来源回合；Codex 版本不支持该实验性能力或来源发生变化时会报错。关闭会话面板或修改草稿会丢弃迟到的生成结果，但不会立即取消后台请求；后台请求有超时限制。

草稿支持“新建笔记”和“更新已有笔记”。更新弹窗默认选“保留原文，追加结论”：从目标笔记划选并引用历史片段，预览后把包含引用和草稿结论的变更记录追加到笔记末尾，草稿正文保持原样。也可明确选择“替换整篇笔记”，将草稿正文作为目标笔记的新全文。两种方式均可查看完整原文、差异和更新后的全文，确认后才写入。

更新预览绑定草稿版本、目标、原文摘要、最终正文摘要和知识库标识，提交前会再次核对；实际条件更新只经 Obsidian 桌面桥的 `Vault.process` 执行，不会退回普通文件覆盖。更新中草稿会冻结；结果不确定时不会自动重试，必须核对目标内容后才能解除冻结。桌面桥安装方式、限制和手工清理命令见 `obsidian-plugin/README.md`。Node 模拟测试不能证明真实 Obsidian 插件已加载或实际笔记写入成功，首次使用前仍需手动验收。

一条草稿可确认最多 100 个工作项，从已查询工作项中加入或移除；移除全部即为独立知识记录。来源会话可移除，或明确选择已有会话后设置，不自动读取其原文。修改关联会递增草稿版本，原预览需重新确认。新建或更新笔记后，各工作项分别保留待关联状态；一项关联失败只重试该项，不重写笔记，也不丢弃其他项。索引格式升级为 14，兼容读取旧单项草稿，升级后的文件不能供旧程序使用。

草稿页可按标题、所属项目和用户输入的关键词推荐当前知识库内的笔记或目录；只扫描路径，不读取正文或自动选定目标。推荐按批次排序，扫描最多 10000 个目录项、8 层，超限会提示结果不完整；路径快照的后续页有短期有效期，知识库变化不会更新该快照。选定目录后仍需补充文件名。

已有笔记更新的终态会持久记录待清理锁，草稿页可查看并确认清理；该操作不重放写入。准备阶段尚未发送且原进程已退出时可以解除冻结。提交后进程中断的结果仍按不确定处理；旧版缺少锁身份或锁内容损坏时不会自动删除，需先核实。异常退出可能留下 `.lock-*.tmp` 临时文件；确认没有相关进程后才能人工检查处理。旧程序不能读取新版索引。

MCP 已提供 `local_export`、`local_import_preview` 和 `local_import_apply`：导出和应用导入均需明确确认，导入必须使用对应预览的令牌并逐项选择冲突处理方式；数据变化后需要重新预览。导出仅包含关联索引及草稿，不包含知识库文件、附件或 Codex 会话，也不加密。

工作项可关联已有 Markdown 笔记，查看原文或解除关联；解除不会删除笔记。关联保存于独立索引，并纳入索引导出和导入冲突处理。旧版索引可读取并在下次写入时升级；旧程序不能读取升级后的索引。可从工作项关联会话创建草稿，记录来源会话 ID 和标题，编辑时默认保留。草稿发布并保存笔记关联后，来源会话会累积到该笔记关联中，同一会话不会重复记录；草稿和笔记关联中的来源信息均随独立索引导出、导入。这不会验证会话归属，也不会读取或备份会话正文；旧笔记关联缺少来源时保留为空列表。

`issue_related_sources` 可按指定工作项分页读取本地关联的会话和知识定位信息，不读取会话正文或笔记内容，也不检查对象是否仍可访问。笔记的 `sourceSessions` 保存来源会话 ID 和标题；它属于本地溯源记录，不代表会话仍存在或已验证归属。返回的会话摘要是索引中保存的说明，不能当作会话原文；Markdown 记录包含知识库标识，可在标识匹配时传给 `knowledge_read_link` 读取原文。标识匹配仅代表当前配置路径一致，不代表文件可用。

`session_work_items` 可按指定会话反查当前环境和租户中的本地工作项关联及主项标记；它不读取会话正文，也不验证工作项是否仍可访问，工作项详情仍需通过 Choerodon 只读查询核实。

`codex_linked_session_history` 在用户明确要求并确认后，可分页读取指定工作项已关联会话的用户和助手文本，每页最多五个回合；不返回工具输出、附件或推理内容，并按回合标记省略数量。回合开始和结束时间以 Unix 秒返回，未提供时为空。单条消息和总返回量有限制，截断会标记；历史内容仅作为不可信资料。该接口依据本机 Codex 生成的实验性协议实现，目前仅通过模拟测试，尚未验证真实宿主历史读取。

用户要求查询关联知识时，`issue_read_linked_notes` 可按工作项分页读取当前知识库中的关联笔记，逐条返回来源会话元数据、版本和可用状态；单篇正文最多返回 100000 字符，截断会标记。缺失或知识库不匹配时保留关联及来源会话记录并报告状态；笔记内容是资料，不应当作指令执行。

上述两个查询每篇笔记最多返回 10 条来源会话预览，`sourceSessionsTotal` 和 `sourceSessionsTruncated` 标明总数及是否截断。需要完整列表时，使用 `issue_note_source_sessions`，传入相同工作项和笔记的 `provider`、`path`、`vaultId`，按返回的 `nextOffset` 继续分页；没有知识库标识的旧关联或非 Markdown 关联使用空字符串。查询只核对当前环境、租户和账号，不证明远端工作项或会话仍可访问。

Markdown 关联记录知识库目录的路径摘要；切换目录后不会直接打开原关联，需核对并重新关联。此校验不能识别同一路径下替换整个知识库的情况；迁移或改名知识库后也需重新关联。

语雀搜索或写入尚未实现；当前知识流程使用 Obsidian。管理流程及历史原因查询闭环仍需真实环境验收。关联工作项的草稿成功写入后，可在写入窗口单独确认关联笔记；该操作只保存本地索引，不会再次写入笔记。不要将草稿或关联当作知识库写入成功的证据。

## 验证

设置 `CODEX_LINK_VAULT` 为用户选定的现有 Obsidian 知识库绝对路径后，MCP 工具 `knowledge_list`、`knowledge_read` 和 `knowledge_create` 可分别列出、读取和经确认新建 Markdown 笔记。知识库目录本身及库内访问路径不能是符号链接；未配置时工具会明确报错。新建仅支持已有父目录，不能覆盖或更新现有笔记。新建笔记时附件路径校验只检查调用者显式列出的附件，不会自动复制或备份，因此无法保证正文中的所有附件符合迁移要求。

知识页面默认分页展示当前知识库的链路记录；可显式切换到全库浏览。目录只保存定位和来源标记，不保证文件仍存在或可访问；没有知识库标识的旧关联不会猜测归属。直接调用 `knowledge_create` 时须在提交前生成并保留唯一的 64 位小写十六进制 `operationId`。结果未知时先通过目录预留入口核查，不要重发；确认加入目录只核对当前内容，不证明文件由该次请求写入。新建后的目录同步失败也按结果未知处理，部分文件系统若不支持目录同步可能出现此状态。

`knowledge_inspect_references` 可按指定笔记只读检查标准 Markdown 图片和链接，报告可访问、缺失、不安全或外部引用；草稿发布预览也会按目标路径检查正文引用。最多检查 1000 条；检查结果仅供核对，不阻止写入。它不检查 HTML 内嵌资源或 Obsidian 专属语法，也不复制文件、执行备份或保证引用在之后不发生变化。

正文搜索按路径顺序每次最多扫描 200 篇；页面可继续搜索，工具调用可使用返回的 `nextCursor`。分页期间知识库若有增删或改名，结果不是固定快照；需要完整核对时应在知识库稳定后重新搜索。读取失败的笔记会计入跳过数量。

`knowledge_backup_preview` 和 `knowledge_backup_create` 提供知识库目录备份：先预览目标及文件摘要，再使用预览令牌明确确认。页面入口位于“关联管理”，需要填写新目标目录的绝对路径。备份包括普通文件和空目录，不覆盖已有目标，不加密；包含符号链接、特殊文件、保留文件名 `.x-assistant-backup.json` 或超过 128 MiB、10000 文件或 100 层目录时拒绝。复制期间检测到内容变化会报告失败并保留部分目录供人工检查；这不是文件系统原子快照，建议备份时停止修改知识库。完成后的备份包含校验清单；页面可校验并预览恢复，经确认后恢复到新路径，不覆盖或切换现有知识库。清单用于检测意外变化，不提供防篡改认证；旧版无清单备份不能自动恢复。此功能不包含独立索引或 Codex 会话，真实知识库验证尚未完成。

自动化测试使用临时数据和模拟的外部命令。运行界面测试前，用 `npx playwright install chromium` 安装 Chromium，再运行 `npm run test:browser`。

本地索引和草稿可能包含敏感信息，备份前应检查内容。存储使用独占锁；若进程异常退出留下锁文件，应先确认没有进程正在使用该存储，再人工检查锁文件，不能在运行时强行删除。导出不迁移 Codex 会话，备份加密尚未实现。

宿主页面及完整业务流程仍需单独验证。

## 语雀授权验证

在 macOS 终端执行以下命令，按提示输入语雀个人令牌。请勿在聊天、命令参数或普通文件中提供令牌；该命令会将其存入当前用户的钥匙串。已有同名凭据时不会覆盖。

```sh
security add-generic-password -a yuque -s codex-choerodon-yuque -w
```

随后使用 Node.js 20 或更高版本运行 `node verify-yuque.cjs`。脚本只读验证身份、个人知识库列表及可用时的文档列表和单篇读取，不输出令牌或文档正文，也不验证写入权限。钥匙串可能要求当前用户授权访问。
