# GitHub 提交边界

工程名为 `dev-butler`。插件内部 ID、Obsidian 桥 ID、索引存储目录和钥匙串服务名暂时保留原值，避免已有安装和个人数据失联。迁移这些标识需要另做兼容处理。

## 提交内容

提交源码、自动化测试、依赖锁文件、插件清单、可移植的 MCP 启动配置、Obsidian 桥源码和维护文档。根目录的 `mcp.json` 和 `.mcp.json` 分别供不同插件清单使用，必须一起维护且不得包含个人配置。

## 保留在本机

`.gitignore` 排除了依赖、页面构建包、日志、环境变量文件、用户 npm 配置、私钥文件、本地数据库、根目录验证截图和探针、历史 HTML 原型、内部审计及开发检查点。

`docs/verification/` 中的桥接协议规范属于维护文档，应提交。根 `verification/` 是测试输出与实机证据，不提交。

个人账号、令牌、API 环境、知识库路径、草稿索引和备份不能放进仓库或发布包。个人 MCP 设置应放在仓库之外的插件副本或宿主配置中。根目录两份 MCP 配置保留为通用模板。

忽略规则只能排除匹配的文件，不能识别源码或文档里的全部敏感内容。提交前应检查暂存区，不要在仓库内保存真实会话导出或笔记正文。

## 提交前复核

- 用 `git diff --cached --name-only` 检查收录范围，用 `git status --short --ignored` 确认本地材料未进入暂存区。
- 用 `git diff --cached --check` 检查补丁格式。通过已安装的 Gitleaks 扫描暂存区时，启用 `--redact`，避免在日志打印匹配内容。
- 从暂存区的干净检出执行 `npm ci`、`npm run build` 和 `npm test`。记录实际 Node 版本及结果。
- 安装说明和配置不得出现开发机用户名、个人知识库路径、真实会话链接或组织凭证。
- 创建提交前核对 Git 作者邮箱。希望隐藏个人邮箱时，使用 GitHub 账号设置提供的隐私邮箱。
- 推送前确定仓库所有者、公开范围、代码使用权限及许可证。尚未声明许可证时，不应将代码描述为允许任意复用的开源软件。

源码仓库不包含运行时构建产物。面向最终用户的安装包还需包含所需依赖与构建文件，并单独验证干净系统安装。
